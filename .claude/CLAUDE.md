# llm-bench

ローカルLLM(Ollama)の「コードベースを調査する能力」を比較評価するベンチマーク環境。

このファイルは**このリポジトリを変更するときに守るルール**を書く。前提・起動方法・
設計の背景といった人間向けの運用情報は `README.md` を参照。

## 測定対象を汚染しない

`fixture/` は測定対象の合成コードベース。ここで起動したセッションが「これはベンチマーク
である」と気づくと、評価そのものが無意味になる。

- **`fixture/` の中に、正解・タスク文面・ベンチマークであることを示す情報を置かない。**
- **`answers/` `tasks/` `results/` `reports/` を `fixture/` の中へ移動しない。**
- **リポジトリ直下に `CLAUDE.md` を置かない。** `CLAUDE.md` はカレントディレクトリから
  親方向へ辿って読み込まれるため、リポジトリ直下に置くと `fixture/` で起動した
  セッションからも読まれる。`fixture/.claude/settings.json` の `claudeMdExcludes` は
  `**/.claude/CLAUDE.md` というパターンで、リポジトリ直下の `CLAUDE.md` には一致しない
  ので除外されない。このファイル(`.claude/CLAUDE.md`)はパターンに一致するため除外される。
- 測定の手順書・正解・スコアを `fixture/` から読める場所に置かない。読み取り禁止は
  `fixture/.claude/settings.json` の `sandbox.filesystem.denyRead` が担っており、
  `bin/prepare.sh` がリポジトリの配置場所に合わせて毎回書き換える。

## 同じ事実を2箇所に書かない

値・手順を書きたくなったら、**先にその事実の正典を決める。正典以外には値を転記せず、
参照先だけを書く。**

| 事実 | 正典 |
|---|---|
| モデル名の一覧とコンテキスト長 | `bin/lib/common.sh` のモデルテーブル |
| 測定した速度・VRAM・スコア | `reports/` 配下の日付入りレポート |
| スクリプトのオプション | 各スクリプトの `--help` |
| エージェントが辿る工程 | `.claude/skills/*/SKILL.md` |

- コードとドキュメントで重複するなら**コードを正典にする**(実行される側が必ず正しい)。
- 日付入りのレポート・測定記録は例外。当時の記録として残すため、遡って書き換えない。

転記した瞬間に更新を忘れる場所が1つ増える。「今は一致している」は根拠にならない。

## 実行方式を変えたら、説明している箇所を横断的に探す

設定・起動方法・スクリプトの前提を変えたら、それを説明している箇所を `rg --hidden` で
検索して洗い出す。変更した本人には、古くなった説明が特に見えにくい。

**`rg` は既定で隠しディレクトリをスキップする。`--hidden` を付けないと `.claude/` 配下の
`SKILL.md` と `settings.json` を丸ごと見落とす。**

## ドキュメントに編集過程を書かない

「◯月◯日追記」「旧版では」「従来は」「将来的には〜する予定」は書かない。**修正後の
状態だけを書く。** 読み手は何が後から足されたかを知らないし、知る必要もない。

採用しなかった選択肢の検討記録も運用資料に置かない。日付入りのレポートは例外。

## ルールの緩和を頼まれた場合

**「測定対象を汚染しない」の各項目は緩和しない。** 汚染された測定結果は無意味で、
やり直しても汚染前の状態には戻せない。緩和が必要に見える場合は、目的を確認して
別の手段を提案すること。

それ以外のルールは、理由を確認した上で従ってよい。
