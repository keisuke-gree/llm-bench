用語集(クリックで展開)
eval rate
モデルが出力を生成する速度(1秒あたりのトークン数)。eval count ÷ eval duration で求まる。入力を読む速度とは別物で、体感速度を支配するのはこちら。
eval count
モデルが生成した出力のトークン数。実際の待ち時間は eval count ÷ eval rate で決まるため、速度だけ見ても待ち時間は分からない。
prompt eval rate
入力(プロンプト)を読み込む速度。全トークンを並列に処理できるため eval rate より速い。
トークン
モデルが文章を扱う最小単位。日本語なら1〜2文字、英語なら単語の一部程度に相当する。
tok/s
tokens per second。1秒あたりに生成できるトークン数。
コンテキスト長
モデルが一度に扱える入力と出力の合計トークン数の上限。これを超えると古い内容が失われる。
KVキャッシュ
生成の途中結果を保持するメモリ領域。コンテキストが長いほど大きくなり、VRAMを消費する。
VRAM
GPUが使えるメモリ。Apple Siliconでは本体メモリと共有される。
PROCESSOR
ollama ps が表示する列で、モデルがGPUとCPUのどちらで動いているかの比率。100% GPU が理想的な状態。
SIZE
ollama ps が表示する列で、そのモデルがメモリ上で占める大きさ。モデルの重みとKVキャッシュの合計。
CPU溢れ
モデルがVRAMに収まらず一部がCPU側で処理されること。オフロードとも呼び、速度が激減する。
MoE
Mixture-of-Experts。モデル内部を複数の「専門家」に分け、1トークンごとに一部だけを使う構造。総パラメータが大きくても計算量が少なく高速。
dense
MoEと対になる構造で、1トークンごとに全パラメータを使う。同じサイズならMoEより遅くなる。
メモリ帯域
メモリからデータを読み出せる速さ(GB/s)。denseモデルの速度上限を決める物理的な制約。
量子化
モデルの重みを低い精度に圧縮してサイズを小さくする技術。
thinkingモード
回答の前に思考過程を生成するモデルの動作。精度が上がることがあるが生成トークンが増えて時間がかかる。
auto-compact
会話がコンテキスト長の上限に近づいた際、Claude Codeが自動で要約して圧縮する機能。
デコイ
ベンチマークで意図的に仕込んだ「正解に見えるが正解ではないもの」。判別能力を測るための罠。
幻覚
hallucination。モデルが存在しないファイルや関数を、あたかも存在するかのように出力すること。
学習データ汚染
評価に使うコードがモデルの学習データに含まれており、実際には調査せず記憶で答えられてしまう問題。
rg
ripgrep。高速な文字列検索コマンド。
fd
高速なファイル探索コマンド。
テンプレートトークン
モデルが内部的に使う制御記号。出力に漏れると表示が壊れたり、ツール呼び出しが失敗する。
